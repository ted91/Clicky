Speaker Identification

Recognizes a person's voice across recordings and suggests their name automatically — entirely local, embeddings never leave this device (unlike transcription/summarization, which do go to whichever cloud provider you've configured under Providers). On by default: this pulls in a real ML dependency (PyTorch + SpeechBrain), noticeably larger than the rest of the app, and downloads a ~80MB model the first time it's used.

Your own voice is enrolled automatically from meeting recordings (no action needed). Everyone else is enrolled the first time you name a speaker — future recordings then prefill a recognized speaker's name as a suggestion (never silently applied); typing a different name corrects it and re-trains that voice going forward.

Providers

Transcription and summarization are independent choices — mix e.g. local transcription with a cloud LLM.

Transcription & summarization
Crosstalk filtering

At a noisy venue, the device's single mic can pick up a nearby unrelated conversation alongside the real one. This classifies noticeably quieter/more-distant speech as background and excludes it from the summary (transcript still shows everything). It's a mitigation, not true speaker separation — two people talking over each other at similar volume can't be untangled by this. Disable it if it ever misfires on a legitimately quiet-but-relevant speaker.

Notion

Every processed recording is pushed here automatically once configured — Notes, plus optional Tasks/People/Calendar/Journal databases.

Auto-setup (recommended)

Creates the Notes/Tasks/People/Calendar databases automatically, wired up with the right columns and relations.

1. In Notion, create a Teamspace for this (sidebar → Teamspaces → +) — the public API can't create a Teamspace itself.
2. Inside it, create one blank page (any name, e.g. "Clicky").
3. Create an integration at notion.so/my-integrations, copy its "Internal Integration Token".
4. Share that page with the integration (••• menu on the page → Connections → your integration).
5. Paste the token and the page's ID below, then run setup.

Only run this once per workspace — running it again creates a duplicate set of databases.

Manual (only needed if you skipped auto-setup)

1. Create an integration at notion.so/my-integrations, copy its token.
2. Create (or pick) a database, share it with that integration (••• → Connections).
3. Copy the database ID from its URL (the 32-character part before any "?").

Tasks (optional)

One page per action item. Columns: Name (title), Status (status), Due Date (date), Assignee (person — exact name match only), Related Note (relation → Notes). Enable "Read user information" under your integration's Capabilities for Assignee matching.

People (optional)

One page per person mentioned. Columns: Name (title), Note (text), Email (email — matched against calendar attendees so recordings with the same person stay linked to one page), Related Note (relation → Notes).

Calendar (optional)

One page per calendar event mentioned. Columns: Name (title), Date (date), Related Note (relation → Notes).

Journal (optional)

Self-reflective recordings (no tasks, no one else substantively involved) get pushed here in addition to Notes. Point this at Notion's own "Journal" template, or any database with a title and a Date property.

Google

Reads your calendar to auto-detect meetings (Meet or Teams links — Teams works fine even on a Google calendar) and pull attendee names/emails for better speaker naming and Notion People matching. Also lets you send a summary email, create a Google Task, or book a follow-up event after a meeting — nothing is ever sent without you clicking Approve on the dashboard first.

Jarvis

Press BOOT to capture a spoken command (finish with BOOT again, same as PWR/Record) — the device speaks a reply back through its own speaker. Only "Q&A" questions use the LLM provider configured under Providers; calendar events, reminders, and email drafts are handled entirely by local Mac apps (Calendar.app, Reminders.app, Mail.app) via AppleScript automation — the first time each is used, macOS will prompt for Automation permission (and, for naming a different assistant app like ChatGPT, Accessibility permission too) in System Settings → Privacy & Security. Genuine coding requests ("build this feature in...", "fix the bug in...") always go through the real Claude Code CLI, scoped to the repo folder below — install it separately if you haven't already. Every Jarvis command is also logged as a note under a "Jarvis" folder in your Obsidian vault, if one is connected below.

Obsidian stores everything locally on this computer — high privacy, but you can't access the data without this machine. Notion stores data in the cloud — not local, but you can reach it from anywhere.

Device API key

Live voice agent (experimental)

When the device has WiFi, BOOT-captured commands stream live to a Deepgram Voice Agent instead of recording a clip and waiting for this app to process it later -- plain questions get answered immediately, even if this Mac is turned off. Reuses your Deepgram key from Providers; only a Groq API key (free tier) is new -- Groq runs the "what to do" decision cheaply/fast. Actions (calendar/email/etc.) are still forwarded here to actually execute -- this Mac must be reachable for those, same as today.

Obsidian

No account needed — everything is written as markdown files directly into your vault folder on disk; Obsidian picks them up automatically. Full parity with Notion: a note per recording (vault root), plus Tasks/People/Calendar notes, a Journal note for journal-classified recordings, and a Publications note per recording for social posts. Approvals/scheduling use Obsidian's Properties panel — checkboxes like approve_send or approve_linkedin and date pickers like linkedin_scheduled_at are read back automatically. Check the generate_social_media checkbox on a recording's note (or its Journal note) to generate social posts on demand.

People

Adding a stakeholder's email or LinkedIn (from a recording's Stakeholders list) links them across recordings even when their name is spelled differently each time -- contact info wins over name matching. This scans for existing People pages that already share an email/LinkedIn under different names, so you can merge them.

Social Media Accounts

See Social Media Posting (site nav, left) for a read-only view grouping each recording's posts together.

Substack ⚠️ unofficial

Substack has no official API. This uses an unsupported, reverse-engineered library that drives Substack's own internal endpoints via your session cookie — it can break without notice on any Substack frontend change, and automated use of internal endpoints likely violates Substack's Terms of Service (including account-level risk). Only proceed if you accept that risk.

Medium — manual only

Medium closed new API integrations in Jan 2025 — no automated publish path exists. Each recording's Medium draft gets a "Download markdown" button under Social Media Posting (site nav, left); paste it into Medium's own editor or Import a story, then paste the resulting URL into that post's "Post URL" property in Notion — that's what tells the LinkedIn/X teaser it's safe to go out with a real link.
